Agent 辅助阅读器设计文档

AI 辅助深度阅读工具：整书理解、概念图解（可交互动画为主）、页面涂写提问。第一版为单用户自用的纯网页应用，首批书型为经济学类书籍。

版本 v1 · 评审 4 轮 4 条里程碑 3 条红线 已定稿 · 正式文档见 2026-08-31_agent辅助阅读器.md

目标

构建一个 AI 辅助的深度阅读工具。AI 对整本书建立理解后，将书中晦涩的概念、案例转换为静态图片与可交互式动画，辅助读者理解；读者可直接在阅读页面上涂写（圈选、划线、手写）向 AI 提问，而非依赖传统对话框。

范围（第一版，自用）

  • 单用户、单机自用；不做账号体系、多用户、计费。
  • 首批书型：经济学类书籍（供需曲线、统计图表、公式模型为重点解析对象）。
  • 书籍来源：用户自行上传 PDF / EPUB 文件；不建书库、不做内容分发。
  • 产品形态：纯网页应用（浏览器访问，本地后端服务承载）。

非目标（明确不做）

  • 扫描版 PDF 的 OCR 支持（二期）。
  • 手写笔（压感/防误触）深度优化（二期；第一版以鼠标/触摸板为目标）。
  • 产品化所需的多租户、计费、版权采购（后置）。

分层架构（上层只许调用下层，禁止反向依赖）

交互层

阅读页面渲染、透明涂写画布层、页边图解卡片、可展开侧边栏

Agent 层

整书理解（混合式上下文管理）、涂写意图识别、讲解与图解的编排生成

生成层

LLM 代码生成可交互动画（主）+ 文生图静态图片（兜底），沙箱渲染

书籍层

PDF/EPUB 解析为结构化章节数据（目录树、段落、图表位置）

↑ 上层只许用下层，不许反着来

技术选型（执行时可等价替换，替换需在文档中登记）

  • 前端：EPUB.js 渲染 EPUB；PDF.js 渲染文字版 PDF；Canvas 覆盖层实现涂写；页内嵌入卡片以段落锚点挂载。
  • 后端：本地服务（Python FastAPI 或 Node.js 均可），承担书籍解析、上下文管理、模型路由、生成调用与缓存。
  • 模型路由（国产阵容，按能力分工）：长文理解/问答走 Kimi（长上下文）或 DeepSeek（低成本）；涂写截图理解走 Kimi 或 GLM 的视觉版本（DeepSeek 主系列无视觉能力，不可用于此路径）；静态图片生成走可用的文生图服务。

3.1 书籍解析模块

  • 输入：PDF / EPUB 文件；输出：BookDoc 结构化数据。
  • BookDoc 结构：{meta, toc[], chapters[{id, title, paras[{id, text}]}], figures[{id, chapterId, imgPath, caption}]}
  • 段落 ID 必须稳定（章节序 + 段序生成），作为引用回跳与页内卡片挂载的锚点。
  • 统计表格、曲线图提取失败时保留原区域截图，不强行文本化，不输出乱码进上下文。

3.2 上下文管理模块（混合式，决策 D2）

  • 常驻上下文：全书摘要（每章 200~400 字）+ 目录地图 + 术语表。
  • 动态装载：当前阅读章节全文进入上下文，切换章节时替换。
  • 旁证检索：章节分块建立向量索引；跨章节问题先检索再装载相关块。
  • 必须启用模型服务商的上下文缓存机制（重复前缀只计费一次）。

3.3 问答与引用模块（红线 2 的执行载体）

  • 所有回答必须携带引用：{paraId, quote}[]，前端渲染为可点击链接，点击跳回原段落。
  • 书中无依据的问题，必须明确回答"书中未涉及"，禁止编造。

3.4 图解生成模块（决策 D3 + D6）

  • 触发时机：随读随生成（用户提问或涂写触发），不做全书预生成。
  • 主路径：LLM 生成自包含 HTML/SVG/JS 小组件 → 隔离沙箱（iframe sandbox，禁止网络访问）渲染 → 失败自动重试 1 次 → 仍失败降级为文生图静态图片 + 文字讲解。
  • 缓存键：书籍 ID + 段落 ID + 概念规范化名；同键只生成一次，重复请求直接命中缓存。
  • 每张图解卡片必须带"辅助理解，以原文为准"标注，讲解文字默认折叠、可展开。

3.5 涂写交互模块（决策 D4 + D5）

  • 页面覆盖透明 Canvas 记录笔迹；设"阅读 / 圈选"模式开关，避免与翻页手势冲突。
  • 圈选完成后：截取该区域书页 + 笔迹合成图 → 发送视觉模型解析"指向哪段、问什么"（用户可选附一句文字补充）→ 转入 3.3 / 3.4 流程。
  • 回答呈现：页内嵌入卡片锚定在所圈段落旁；卡片提供"展开到侧边栏"操作，展开后继承上下文继续多轮对话。

3.6 成本闸门模块（红线 3 的执行载体）

  • 生成类调用缓存优先；每会话设生成频率限制；累计费用在界面可见。

🚫

红线 1：书籍内容不许外流、不建书库

用户上传的书只用于本人阅读会话，不转存分发、不提供给其他用户、不用于模型训练。

🚫

红线 2：AI 讲解不许脱离原书瞎编

所有回答与图解必须锚定书中真实章节内容并可点回原文；图解必须带"辅助理解，以原文为准"标注。

🚫

红线 3：生成必须有成本闸门

缓存（同概念只生成一次）、频率限制、费用可见，三者缺一不可，预算不敏感期间同样保留。

M0 能打开书

5 本经济学类 PDF/EPUB 翻页、跳章无卡顿；段落文字可选中；目录跳转 100% 准确。

M1 能聊书

20 个跨章节问题的回答引用出处 100% 真实可查；对书中无依据的问题 100% 明确回答"书中未涉及"。

M2 能画图

10 个真实晦涩概念生成图解，人工评审"确实帮助理解"比例 ≥ 7/10；动画生成失败场景 100% 有降级输出；同一概念二次请求 100% 命中缓存。

M3 能涂写

零打字纯涂写完成 5 次提问，AI 正确定位所指段落 ≥ 4/5；页内卡片可展开到侧边栏且对话上下文连续。

D1产品形态 → 纯网页应用

零安装、验证最快；桌面应用多平台维护成本高；浏览器插件 PDF 场景能力弱。第 2 轮，用户拍板。

D2整书理解 → 混合式

整本常驻又贵又慢；纯 RAG 损伤跨章理解。全书摘要+目录地图常驻，当前章装载，旁证检索；必须启用上下文缓存。第 2 轮，用户拍板。

D3动图生成 → 代码生成可交互动画

最生动、利于理解；失败自动降级静态图+文字。落选：纯图片不能交互；视频生成分钟级延迟。第 2 轮，用户拍板。

D4涂写理解 → 圈选截图+笔迹提示

区域截图交视觉模型，可选附一句话，最接近"随手一圈"。落选：手写识别对潦草字迹不准；仅划线自由度低。第 2 轮，用户拍板。

D5AI 位置 → 页内为主+侧边栏兜底

问答锚定书页保持阅读流；深聊可展开侧边栏继承上下文。第 2 轮，用户拍板。

D6生成时机 → 随读随生成

不预生成、不浪费；同概念缓存复用只生成一次。第 2 轮，用户拍板。

需求边界确认（Q1~Q4）

  • Q1 首批读者为本人自用（第 2 轮）；书型为经济学相关书籍（第 3 轮由"金融"修正）。
  • Q2 模型用国产 DeepSeek / Kimi / GLM，预算暂不敏感，但成本闸门保留（第 2 轮）。
  • Q3 先自用、产品化后置（第 2 轮）。
  • Q4 书籍由用户自行上传（第 2 轮）。

扫描版无文字层、双栏乱序、公式图表乱码；经济学书的统计表格单元格对齐、曲线图坐标标签是重灾区。

规避：M0 先支持 EPUB 与文字版 PDF，扫描版列二期；5 本真实经济学书实测通过后再往下走。

代码生成不是每次都成功，且有安全风险。

规避：沙箱隔离运行；失败重试 1 次后降级静态图+文字。

百万字每次重算费用高、首字延迟可能超 10 秒。

规避：D2 混合式 + 必须启用上下文缓存。

手写笔要求高（压感、延迟、防误触）。

规避：第一版以鼠标/触摸板为目标；涂写层与翻页手势用模式开关隔离；手写笔优化列二期。

DeepSeek 主系列为文本模型无法看图，路由选错则涂写功能失效。

规避：截图理解走 Kimi/GLM 视觉版本；M3 动手前实测视觉模型对"书页+手写笔迹"截图的识别率。
