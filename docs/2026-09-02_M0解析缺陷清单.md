## 开发中当场修复的缺陷

| # | 缺陷 | 修复 |
|---|---|---|
| 1 | ebooklib 读回的 EPUB 导航文档 `properties` 丢失，nav.xhtml 被当作正文章节 | `_is_nav_document` 内容特征识别（`<nav epub:type=toc>`） |
| 2 | epub.js ESM 入口在 Vite 预打包下渲染队列死锁 | 改用包内 UMD 构建 + 经典 `<script>` 注入（`epubCompat.ts`） |
| 3 | epub.js UMD 需要全局 JSZip，缺失时报 "JSZip lib not loaded" | 注入顺序：先 jszip 后 epubjs |
| 4 | 内嵌 WebView / 后台标签页 rAF 停摆导致 epub.js 队列永久卡死 | 自适应 rAF 垫片（真 rAF 与 32ms 宏任务先到先得） |
| 5 | `dataset.paraId` 的 camelCase 映射成 `data-para-id`，锚点选择器失配 | 统一 `setAttribute("data-paraid", …)` |
| 6 | React StrictMode 双跑 PDF 渲染 effect，同一 canvas 二次 render 挂死 | renderTask 取消 + 逐 await 的 cancelled 检查 |
| 7 | 合成书生成器 `_policy` 占位符未替换 | 修正模板 |
| 8 | PDF 文本层段落 span 双重偏移（place 先于段落盒定位执行，选中层与 canvas 错位） | 先量测→建盒定位→再按盒原点相对放置 span（评审 E1） |
| 9 | EPUB 跨章目录锚点跳转不落段（pendingPara 消费逻辑被误删成死存储） | annotate 末尾恢复跳转落点消费（评审 E2） |
| 10 | biome lint 基线红（eslint-disable 注释不被 biome 识别等 22 处） | biome-ignore 注释 + noForEach/非空断言整改（评审 E3） |
| 11 | E1 首次修复有误：span origin 传了 item 自身几何，多 item 段落全部堆在段落盒 (0,0) | origin 改传段落盒原点；放置数学抽为纯函数 pdfLayout.ts 并补回归测试（第 2 轮复审） |
| 12 | pdfjs 未配 cMapUrl/standardFontDataUrl，CJK 非嵌入字体 PDF 浏览器端无文本层且 render 挂死 | 资产经 setup:assets 拷入 public/pdfjs，getDocument 传入三参数；浏览器实测 111 span 文本层 + 目录跳转全通（第 2 轮复审 N1） |
| 13 | PDF 文本层被内联样式写成 relative，在 canvas 下多占一份高度（页码指示被推出视口） | 移除内联覆盖，保持类名 absolute inset-0 |

## 已知限制（明确范围，不在本期修）

1. **扫描版 PDF**：无文字层直接拒识并提示（上游 R1 列二期），行为符合预期。
2. **PDF 段落重组是启发式**：垂直间距 / 字号跳变 / 项目符号 / 标题行 / 页界共同判定。极端排版（诗歌、代码块密集、竖排）可能分段偏粗或偏细；段落 ID 在同一文件内始终稳定，不影响引用与跳转。
3. **双栏检测阈值**：左右栏各 ≥4 行且跨栏行 ≤25% 才按栏序；三栏、跨页表格不保证。
4. **矢量图表兜底**：仅处理「矢量密集(≥15 条绘图指令) + 文字稀疏(<600 字/页) + 占页面积 ≥15%」的页面；装饰线较多的正常页面不会误伤，但复杂图文混排页的表格可能整体截图进 figures 而非结构化文本。
5. **EPUB 目录锚点**依赖书内 nav/ncx 的锚点 id 与段落元素 id 对应；无 id 的目录项只精确到章。
（原第 6 条「pdf.js canvas 渲染在个别内嵌 WebView 中挂起」已定位根因并解决：缺 cMap 配置导致 CJK 非嵌入字体加载失败、render promise 挂死。见下方修复项 12。）

## 用户人工验收清单（真实浏览器，对应上游 R1 闸门）

1. 准备 5 本真实经济学书（EPUB ≥2 本、文字版 PDF ≥3 本），`scripts/dev.sh` 起服务后经书架上传。
2. 逐本检查：翻页（←/→、PgUp/PgDn）无卡顿；跳章顺滑；段落文字可选中；目录每项点击跳转准确。
3. PDF 书打开确认 canvas 与文本层正常（开发环境已完成合成书实测；真实书再复验）。
4. 视口检查：2560×1440 书页 + 双页边完整、无横向滚动；≈1024px 页边收起、底部便签堆叠区出现；<768px 出现「不支持」提示。
5. 发现乱码 / 乱序 / 图表丢失个案，登记到本文档「用户实测记录」小节。

### 已知限制（明确范围，不在本期修）

1. **EPUB 截图合成是文本重绘**而非像素截取（iframe DOM 无原生截图 API）：视觉模型看到的是按原位绘制的白底黑字行 + 红笔迹，对文字型书页等价；图文混排圈的图片部分不会进入合成图（PDF 路径无此限制，直接裁 canvas 像素）。
2. 便签定位对 epub.js 分栏的预载 iframe 已做离屏过滤；极端快速翻页时便签位置有 1 帧滞后（relocated 信号驱动重算）。
3. 上下文注入（T3.4.4）以「问题文本前缀附便签问答对」实现，未占用独立消息槽；真实模型下如效果不佳，M4 考虑后端显式多轮接口。
4. 视觉意图解析 mock 看不见图（按附言关键词匹配候选段落），接口与真实视觉模型完全一致（同格式消息），真实识别率见 R5 清单。
