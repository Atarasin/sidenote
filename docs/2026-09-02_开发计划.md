## 0. 总览

| 里程碑 | 目标 | 依赖 | 对应上游验收 |
|---|---|---|---|
| M0 能打开书 | 阅读器壳子：解析 + 渲染 + 阅读壳 UI | 无 | 上游 §6-M0；UI §6-U1 |
| M1 能聊书 | 混合式整书理解问答 | M0 | 上游 §6-M1 |
| M2 能画图 | 概念图解（生成 + 沙箱 + 降级 + 缓存 + 成本闸门） | M1 | 上游 §6-M2；UI §6-U4 |
| M3 能涂写 | 涂写提问（涂写层 + 意图解析 + 便签卡 + 对话抽屉 + 费用呈现） | M2 | 上游 §6-M3；UI §6-U2/U3/U5/U6 |

全局约束（每个任务都必须遵守，来自上游红线与 UI 红线）：

1. 书籍内容不外流、不建书库；所有数据只存本地。
2. 所有 AI 输出必须锚定原文：回答带 `{paraId, quote}[]` 引用；图解带"辅助理解，以原文为准"标注；无依据必须答"书中未涉及"。
3. 生成类调用：缓存优先 + 会话频率限制 + 费用可见，三者缺一不可。
4. 段落锚点只用 BookDoc 的稳定 `paraId`（章节序 + 段序），不引入第二套锚点体系。
5. 对话抽屉默认关闭、浮层呈现；书页布局在任何浮层状态下不重排。

工程约定：

- 技术选型按上游 §2.2 执行；等价替换时必须登记到上游文档。
- 每个 Slice 完成 = 代码完成 + 对应验收项通过；里程碑完成 = 该里程碑全部验收标准通过后才允许进入下一里程碑（上游 R1：5 本真实书实测通过后再往下走）。

## M0 能打开书（阅读器壳子）

目标：用户上传 EPUB / 文字版 PDF，能翻页、跳章、选中段落文字；阅读壳 UI 就位。

### Slice 0.1 项目脚手架与工程基线

- T0.1.1 初始化仓库结构：前端（构建工具 + 基础框架）、后端（本地服务，FastAPI 或 Node.js 二选一并登记）、共享类型定义目录。
- T0.1.2 定义本地存储布局：书籍原文件、BookDoc JSON、全书摘要缓存、向量索引、图解缓存、费用记录。
- T0.1.3 书籍上传接口与页面入口：接收 PDF/EPUB 文件，落盘并触发解析；不做书库管理界面。
- T0.1.4 开发基线：lint/format、最小冒烟测试脚本、本地启动脚本（前后端一键起）。

### Slice 0.2 书籍解析模块（上游 §3.1，书籍层）

- T0.2.1 定义 BookDoc schema 与序列化：`{meta, toc[], chapters[{id, title, paras[{id, text}]}], figures[{id, chapterId, imgPath, caption}]}`。
- T0.2.2 稳定段落 ID 生成：章节序 + 段序；同一本书重复解析结果一致。
- T0.2.3 EPUB 解析器：目录树、章节切分、段落抽取、内嵌图片提取为 figures。
- T0.2.4 文字版 PDF 解析器：文本层抽取、阅读顺序还原（双栏按栏序）、段落重组。
- T0.2.5 图表兜底策略：统计表格 / 曲线图提取失败时保留原区域截图进 `figures[].imgPath`，不输出乱码文本进上下文。
- T0.2.6 解析结果落盘缓存：同文件哈希不重复解析。

### Slice 0.3 阅读器渲染集成

- T0.3.1 EPUB.js 集成：渲染章节、翻页、段落文字可选中。
- T0.3.2 PDF.js 集成：文字版 PDF 渲染，同样满足可选中、可翻页。
- T0.3.3 渲染层锚点打通：渲染产出 DOM 与 BookDoc `paraId` 一一对应（供跳转、便签定位复用）。
- T0.3.4 目录跳转：`toc[]` 点击跳转到对应章节/段落，准确率 100%。

### Slice 0.4 阅读壳 UI（UI 文档 U1 / §3.1）

- T0.4.1 三区栅格布局：顶部工具条（40px）+ 中央书页（max-width ≈46rem，纯白）+ 左右页边便签区（各约 15rem，本里程碑先留白占位）。
- T0.4.2 纸感主题：页面底 `#faf9f6`，正文衬线字体栈 `"Noto Serif SC","Songti SC","SimSun",Georgia,serif`，UI 控件无衬线栈。
- T0.4.3 顶部工具条内容：书名 · 当前章节标题；模式开关与费用显示的位置占位（功能在 M3/U6 接入）。
- T0.4.4 目录拉手：书页左缘竖排"目录 ⟨"，hover/点击滑出章节树（数据 `toc[]`），点击跳转。
- T0.4.5 窄屏降级：视口 <1024px 时页边便签区收起、便签位退化为书页底部堆叠（固定高度可滚动区）；<768px 不支持。
- T0.4.6 翻页快捷键沿用 EPUB.js / PDF.js 默认（`←/→`、`PgUp/PgDn`）。

### Slice 0.5 M0 实测与验收

- T0.5.1 准备 5 本真实经济学书（覆盖 EPUB 与文字版 PDF），实测翻页、跳章无卡顿、段落可选中、目录跳转 100% 准确（上游 §6-M0）。
- T0.5.2 UI 验收：2560×1440 最大化下书页 + 双页边完整、无横向滚动；1024px 时降级正确（UI §6-U1）。
- T0.5.3 解析缺陷清单登记：乱码 / 乱序 / 图表丢失个案记录，能修的当场修，修不了的明确范围（扫描版列二期）。

## M1 能聊书（混合式整书理解问答）

目标：对全书建立理解，回答带真实引用，无据必拒答。

### Slice 1.1 模型接入与路由（上游 §2.2 模型路由）

- T1.1.1 模型调用封装：统一客户端（鉴权、超时、重试、错误归一化），API key 走本地配置，不进仓库。
- T1.1.2 模型路由表：长文理解/问答 → Kimi 或 DeepSeek；截图理解 → Kimi/GLM 视觉版（M3 用，本里程碑先留路由位）；文生图 → 选定服务（M2 用，先登记选型）。
- T1.1.3 调用日志与计费统计落盘：每次调用记录模型、token 量、费用（成本闸门的数据源，M2 Slice 2.5 直接消费）。

### Slice 1.2 全书理解构建（上游 §3.2 常驻部分）

- T1.2.1 每章摘要生成：每章 200~400 字；构建产物按书持久化，同书只构建一次。
- T1.2.2 目录地图 + 术语表构建：与摘要一起组成常驻上下文包。
- T1.2.3 构建失败处理：单章失败可重试、可跳过并标记，不阻塞整书。

### Slice 1.3 上下文管理（上游 §3.2 动态部分）

- T1.3.1 常驻上下文装配：摘要 + 目录地图 + 术语表作为每轮固定前缀。
- T1.3.2 当前章节动态装载：阅读章节全文进上下文，切换章节时替换。
- T1.3.3 服务商上下文缓存接入：重复前缀只计费一次（上游红线，R3 规避）；缓存命中率进调用日志。

### Slice 1.4 旁证检索（上游 §3.2）

- T1.4.1 章节分块与向量索引构建：按书持久化；embedding 服务选型登记。
- T1.4.2 跨章问题流程：判定需要旁证 → 检索相关块 → 装载进上下文后再作答。

### Slice 1.5 引用式问答（上游 §3.3，红线 2 执行载体）

- T1.5.1 问答接口：输入问题 + 当前章节上下文 → 输出回答文本 + `{paraId, quote}[]`。
- T1.5.2 引用真实性校验：quote 必须能在对应 paraId 段落原文中字面对上，对不上则丢弃该引用并要求重答/拒答。
- T1.5.3 无据拒答：书中无依据时明确回答"书中未涉及"，禁止编造。
- T1.5.4 问答 API 对前端开放（供 M3 便签卡 / 对话抽屉调用）。

### Slice 1.6 M1 验收

- T1.6.1 20 个跨章节问题实测：引用出处 100% 真实可查。
- T1.6.2 无依据问题集实测：100% 明确回答"书中未涉及"。

## M2 能画图（概念图解）

目标：晦涩概念生成可交互动画，失败必降级，同概念只生成一次，费用可见。

### Slice 2.1 图解生成主链路（上游 §3.4，决策 D3/D6）

- T2.1.1 动画生成提示词工程：输出自包含 HTML/SVG/JS 小组件；强制背景透明、文字/线条用 `currentColor`（UI §3.4 双容器配色约束）；内容必须锚定原文段落。
- T2.1.2 图解生成接口：输入书 ID + paraId + 概念 → 输出组件代码 + 一句话结论 + 引用列表。
- T2.1.3 概念规范化：同一概念的不同表述归一到同一"概念规范化名"（缓存键的一部分）。

### Slice 2.2 沙箱渲染与失败重试（上游 §3.4，R2 规避）

- T2.2.1 iframe sandbox 渲染容器：禁止网络访问、禁止脚本逃逸。
- T2.2.2 渲染失败检测：加载错误 / 空渲染 / 超时均判定失败。
- T2.2.3 自动重试 1 次：失败后换 prompt 修复策略重新生成一次。

### Slice 2.3 静态图降级链路（上游 §3.4）

- T2.3.1 文生图服务接入（选型在 T1.1.2 已登记）。
- T2.3.2 降级输出：重试仍失败 → 静态图 + 文字讲解，"辅助理解，以原文为准"标注不变；降级态写入缓存避免重复烧费。

### Slice 2.4 图解缓存（上游 §3.4 / 红线 3）

- T2.4.1 缓存键：书籍 ID + 段落 ID + 概念规范化名；同键只生成一次，重复请求直接命中。
- T2.4.2 缓存内容：组件代码（或降级静态图）+ 讲解文字 + 引用 + 一句话结论 + 命中标记。

### Slice 2.5 成本闸门（上游 §3.6 / 红线 3，横切）

- T2.5.1 生成类调用缓存优先策略落实（与 T2.4.1 同链路）。
- T2.5.2 会话生成频率限制：计数、阈值、超限拒绝并返回明确状态（供前端"不允许静默失败"文案）。
- T2.5.3 费用数据接口：本会话累计费用、生成次数、缓存命中数、限流状态（消费 T1.1.3 的调用日志）。

### Slice 2.6 图解呈现（UI 文档 U4 / §3.3 小卡 / §3.4 剧场）

- T2.6.1 图解小卡组件：内嵌沙箱组件自动演示 + 文字讲解默认折叠可展开 + 标注行。
- T2.6.2 剧场模式：全屏深色模态（`slate-900` 画布 / `slate-800` 底栏），同一沙箱组件换容器渲染，不重新生成、不产生新生成调用。
- T2.6.3 剧场底栏：一句话结论 + "辅助理解，以原文为准" + `↗ 回到原文 <paraId>` + `继续追问` + `✕`；`✕`/`Esc` 关闭回到触发点。
- T2.6.4 双容器配色验收：浅色小卡与深色剧场渲染一致、文字可读（UI §6-U4）。

### Slice 2.7 M2 验收

- T2.7.1 10 个真实晦涩概念生成图解，人工评审"确实帮助理解" ≥ 7/10。
- T2.7.2 失败注入测试：动画生成失败场景 100% 有降级输出。
- T2.7.3 缓存测试：同一概念二次请求 100% 命中缓存、零新增生成调用。

## M3 能涂写（涂写提问）

目标：零打字纯涂写完成提问，回答钉在页边，可展开深聊，费用与限流显式呈现。

### Slice 3.1 涂写层与模式开关（UI 文档 U2 / §3.2，上游 §3.5）

- T3.1.1 透明 Canvas 覆盖层：覆盖书页，笔迹红色 `#ef4444`；阅读模式下笔迹照常显示但禁用新绘制。
- T3.1.2 模式开关：顶栏"阅读 / 圈选"分段开关（默认"阅读"）+ 快捷键 `A`（200ms 内生效）；阅读模式下鼠标拖拽保持渲染器原生行为。
- T3.1.3 圈选交互：圈选模式按住拖拽画圈，松开即完成一次圈选。
- T3.1.4 附言气泡：圈旁单行输入气泡，留空直发或补一句话；`Esc`/点击圈外取消。
- T3.1.5 区域截图合成：截取圈选区域书页 + 笔迹合成图，连同附言提交后端意图解析接口。
- T3.1.6 快捷键体系：`A`/`D`/`Esc` 全局注册，输入框聚焦时一律失效，每个键均有顶栏等价按钮（UI §3.7）。

### Slice 3.2 涂写意图解析（上游 §3.5，决策 D4，R5 规避）

- T3.2.1 视觉模型预实测：用"书页 + 手写笔迹"真实截图实测 Kimi/GLM 视觉版识别率，结果登记后再继续（上游 R5 要求动手前实测）。
- T3.2.2 意图解析接口：合成图 + 附言 → 输出"指向哪个 paraId + 用户问什么"。
- T3.2.3 意图结果转接：转入问答链路（M1 Slice 1.5）或图解链路（M2 Slice 2.1）。

### Slice 3.3 AI 便签卡（UI 文档 U3 / §3.3，上游 D5）

- T3.3.1 页边定位：按所圈段落 `paraId` 对应 DOM 的 `getBoundingClientRect` 实时计算垂直位置；同屏多张按高度排布、重叠纵向错位 8px；章节切换/缩放后重算。
- T3.3.2 便签结构：标题行（📌 + `图解 · <概念名>` / `讲解 · <问题摘要>`）+ 内容区（图解小卡 + 折叠讲解）+ 标注行（"辅助理解，以原文为准"必带）+ 操作行（`⤢ 剧场放大` / `↗ 原文 <paraId>` / `展开深聊`）。
- T3.3.3 状态机：生成中（提交后乐观占位，骨架 + 转圈）→ 已呈现 → 降级（静态图 + 文字，标注不变）。
- T3.3.4 引用 chips：全部 `{paraId, quote}[]` 渲染为 chips，点击书页滚动到对应段落并高亮闪烁 2s；`↗ 原文` 同逻辑，定位准确率 100%。
- T3.3.5 便签管理：可关闭（仅移除显示，缓存不清）；章末"本章问答清单"入口，列出本章全部便签并可点击定位（具体形态实现时定，见 UI §8 开放问题②）。
- T3.3.6 窄屏降级：视口 <1024px 便签堆叠在书页底部可滚动区，不遮挡正文。

### Slice 3.4 对话抽屉（UI 文档 U5 / §3.5，决策 D4）

- T3.4.1 浮层抽屉：右缘滑出，宽 `min(420px, 40vw)`，覆盖不挤压书页，带投影与左边框；默认关闭、任何状态不自动弹出。
- T3.4.2 三个呼出入口 + 关闭：顶栏"💬 对话"按钮、便签"展开深聊"、快捷键 `D`；`✕`/`Esc`/再按 `D` 关闭。
- T3.4.3 内容三段：头部（`对话 · 接着<章节/便签>聊` + 全书地图入口 + `✕` + 费用同步显示）；对话流（用户消息含圈选截图缩略图与附言；AI 消息含文字、引用 chips、内嵌图解小卡、标注；自动滚到底、上滚停止跟随）；输入行（`✏️` 切圈选态 + 单行文本框 placeholder `补一句话（可不填，直接圈选也行）` + 发送）。
- T3.4.4 上下文注入：继承上游混合式上下文；从便签进入时附加该便签问答对作为局部上下文。
- T3.4.5 抽屉内引用点击：抽屉暂收 → 书页跳转高亮 → 上下文保留可再次呼出。
- T3.4.6 全书地图浮层：抽屉头部与目录面板顶部双入口，展示目录地图、点击章节跳转。
- T3.4.7 布局不变性验收：抽屉开/关前后书页滚动位置与布局零变化（UI §6-U5）；是否支持宽度拖拽实现时定（UI §8 开放问题①）。

### Slice 3.5 费用与限流呈现（UI 文档 U6 / §3.6，红线 3）

- T3.5.1 顶栏常驻累计费用（`¥0.42 · 本会话` 样式），hover 显示明细（生成次数、缓存命中数）；抽屉头部同步同一数据。
- T3.5.2 阈值告警：达会话频率限制 80% 时费用文字变琥珀色。
- T3.5.3 限流显式反馈：触发限制时便签占位态显示"已达频率上限，稍后自动重试"，禁止静默失败。
- T3.5.4 与后端 T2.5.3 费用接口联调：前端显示与后端数据一致。

### Slice 3.6 M3 端到端验收

- T3.6.1 纯涂写实测：零打字完成 5 次圈选提问，AI 正确定位所指段落 ≥ 4/5（上游 §6-M3）。
- T3.6.2 动线效率实测："切圈选 → 画圈 → 留空发送"全程 ≤ 3 次点击 + 1 次拖拽（UI §6-U2）。
- T3.6.3 上下文连续性：便签"展开深聊"进抽屉后首轮回答正确引用该便签上下文（人工判定）。
