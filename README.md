# sidenote · AI 辅助深度阅读器

> 在书页上涂写向 AI 提问的深度阅读器：AI 通读全书，把晦涩概念画成交互动画，旁注钉在页边。

**当前状态：设计已定稿（架构 + UI/UX 均经多轮评审），实现尚未开始。**

---

## 这是什么

读经济学书时，最卡人的是供需曲线、弹性、统计图表这些概念。sidenote 想做的事：

- **AI 先通读全书**，建立整书理解（全书摘要 + 目录地图常驻，当前章节按需装载，跨章问题自动检索旁证）；
- **你在书页上直接涂写提问**——圈选一段、划一道线，而不是切到对话框打字；
- **AI 把晦涩概念画出来**：优先生成可交互的动画（比如能亲手拖动的供需曲线），就地钉在你所圈段落的页边，像一张张旁注便签（这也是项目名 sidenote 的由来）；
- **每个回答都锚定原文**：带可点击的引用，一键跳回书中出处；书中没有的，明确说"书中未涉及"，不编造。

第一版为自己自用：纯网页应用、本地后端、书籍自行上传（PDF / EPUB）、首批适配经济学类书籍、模型用国产阵容（DeepSeek / Kimi / GLM 按能力分工）。

## 核心特性（设计定案）

| 特性 | 说明 |
|---|---|
| ✏️ 涂写即提问 | 圈选 / 划线直接问，可补一句话也可不写；"阅读 / 圈选"模式开关避免与翻页冲突（默认阅读，快捷键 A） |
| 📌 页边便签 | AI 回答以便签卡钉在所圈段落旁的页边；27 寸外屏可并排多张，窄屏自动退化为书页底部堆叠 |
| 🎬 图解剧场 | 概念图解优先用 LLM 生成可交互动画（沙箱渲染，失败自动降级静态图 + 文字）；小卡内嵌，一键放大成全屏"剧场模式" |
| 💬 对话抽屉 | 想连续深聊时呼出右缘浮层对话抽屉（默认关闭、手动触发，快捷键 D），继承便签上下文继续多轮 |
| 🔗 引用锚定原文 | 每条回答、每张图解都带引用 chips，点击跳回原文段落并高亮 |
| 💰 成本闸门 | 同概念只生成一次（缓存复用）、会话频率限制、累计费用常驻可见 |

## 设计定案速览

<details>
<summary>已确认的关键决策（点开查看）</summary>

| 决策点 | 定案 |
|---|---|
| 产品形态 | 纯网页应用（本地后端），零安装 |
| 整书理解 | 混合式：全书摘要 + 目录地图常驻，当前章装载，旁证检索；必须启用上下文缓存 |
| 图解技术 | LLM 代码生成可交互动画（沙箱隔离渲染），失败重试 1 次后降级静态图 + 文字 |
| 生成时机 | 随读随生成，不做全书预生成；同概念缓存只生成一次 |
| 涂写理解 | 圈选区域截图 + 笔迹 → 视觉模型（Kimi / GLM 视觉版）解析意图 |
| UI 整体方向 | 混搭：A 纸感书桌（页边便签）为底 + C 的剧场放大 + B 的对话流收进"默认关闭的浮层对话抽屉" |
| 涂写默认态 | 默认"阅读"模式，按 A 进入圈选 |
| 首批范围 | 本人自用、经济学书籍、国产模型（DeepSeek / Kimi / GLM）、用户自行上传 |

</details>

### 红线（不可妥协）

1. **书籍内容不外流、不建书库**：上传的书只用于本人阅读会话，不转存分发、不用于模型训练。
2. **AI 不脱离原书瞎编**：所有回答与图解锚定真实章节、可点回原文；无依据时明确回答"书中未涉及"；图解必带"辅助理解，以原文为准"。
3. **成本闸门**：缓存、频率限制、费用可见，三者缺一不可。

## 里程碑与路线

```
M0 能打开书 → M1 能聊书 → M2 能画图 → M3 能涂写
（EPUB/PDF 渲染）  （整书问答）  （概念图解）  （涂写提问）
```

交互层任务 U1~U6（阅读壳布局 / 涂写层 / 便签卡 / 图解剧场 / 对话抽屉 / 费用呈现）分别挂接在 M0 / M2 / M3 上，详见 [UI/UX 方案 · 任务分解](docs/2026-09-01_阅读器UIUX方案.md#4-任务分解)。

**技术栈（执行时可等价替换）**：前端 EPUB.js + PDF.js + Canvas 涂写覆盖层；后端 Python FastAPI 或 Node.js 本地服务；模型路由 DeepSeek（文本）/ Kimi、GLM（长文与视觉）。

**二期候选**：扫描版 PDF 的 OCR、手写笔（压感/防误触）深度优化、多书库与产品化（账号 / 计费 / 版权）。

## 工作方式说明

两份设计文档均采用"草图先行"评审：先产出可交互的 HTML 评审草图（大白话 + 待定决策页内点选），逐轮收集反馈迭代留痕，全部决策拍板后才输出面向执行的正式文档。每轮评审意见原文与对应修改都保存在各文档的迭代记录中。
